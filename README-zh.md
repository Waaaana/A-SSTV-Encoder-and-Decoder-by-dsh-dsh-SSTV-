# SSTV Studio

**SSTV Studio 1.2.0**（2026-02-14 发布）· 完整更新历史见 `python sstv_app.py --version`

一套在 Windows 上收发 **SSTV**（慢扫描电视）的程序——业余无线电用来在语音
话路上传送静止图像的模式。

收发两个方向都支持，但同一时刻只做一个方向（SSTV 本身是单工模式）：

| | 输入 | 输出 |
|---|---|---|
| **发送** | 图像文件、内置测试卡，或刚收到的画面 | 扬声器，或 WAV 文件 |
| **接收** | 麦克风、**系统声音**，或 WAV 文件 | 屏幕上的图像（边收边画），可存为 PNG / JPEG |

---

## 运行

双击 **`run.bat`**，或在命令行里：

```
python sstv_app.py
```

想在不打开窗口的情况下检查安装是否正常——它会逐一编码并解码每一种支持的
模式，然后报告结果：

```
run.bat --check
```

另外还有两个命令行用法，适合写脚本，或者不想开界面、只想解码一段录音：

```
run.bat --encode picture.png --mode "Robot 36" --out sent.wav
run.bat --decode recording.wav          # 生成 recording-decoded.png
```

## 使用说明

### 发送图像

1. 打开 **Transmit**（发送）页。
2. 点 **Open image...** 选图——PNG、JPEG、BMP、GIF、TIFF 都行，程序会自动
   把它缩放到该模式规定的精确尺寸。
3. 选择 **Mode**（模式）。
4. 确认 **Send via**（发送设备），点 **Transmit**。

图像一载入就会立刻开始准备音频，所以点 Transmit 是马上出声的。进度条跟随
发送进度，**Stop** 可以在画面发到一半时中断。

**Save audio file...** 不播放，而是把这段发送信号存成 WAV 文件——适合你自己
用电台发出去、走数字模式中继，或者留个存档。

播放音量别调太大：SSTV 自身电平大约在满量程的 80%，声卡推得太响就会削波，
对方收到的画面会被撕开。**Receive** 页的电平条可以让你看到干净信号进来时
应该是什么样子。

### 接收图像

1. 打开 **Receive**（接收）页。
2. 选择信号从哪里来：
   * **Microphone or line input** —— 麦克风，或者把接收机接到声卡的输入口。
   * **System sound (what is playing)** —— 这台电脑正在播放的声音。接收机接在
     音箱上、或者信号在别的程序里播放（比如浏览器里的 WebSDR）时选这个。
     不需要任何连线，也不用把声音从音箱再引回来。
3. 点录制按钮开始，发送结束后再点一次停止；或者点 **Open audio file...**
   直接解码一段录音。
4. 画面会随着解码逐行显示出来，**下面那条瀑布图**会实时滚动显示进来的信号。

监听系统声音用的是 WASAPI 回环技术（loopback），只要声卡能放音就能用。它不依赖
**"立体声混音"** 那个输入设备——那个在现在的声卡驱动里默认是隐藏且禁用的。

保持 **Detect mode from VIS header**（从 VIS 头自动识别模式）勾选，你就不需要
知道对方用的是什么模式。画面下方的信息栏会报告收到的情况：

* 模式名称和它的 VIS 码
* 解出了多少行，以及头部识别的置信度
* 是否做了频率校正、校正了多少
* 找到的同步脉冲有多准

### 没收到 VIS 头怎么办

如果是在对方已经开始发送之后才打开接收，那它的 VIS 头已经过去了——VIS 头只在
最开头发一次。这种情况下程序不会直接放弃，而是**从信号本身推断模式**：每种
SSTV 模式每一行都会发一个同步脉冲，而"行长"正是各模式的区别所在，所以这些
脉冲的节奏就能确定模式。14 种模式都能这样认出来。

推断出来之后，信息栏会写明模式是**推断**的，以及推断的把握有多大——因为推测和
真正读到的不是一回事。有两点需要知道：

* **取景**：SSTV 本身没有场同步，所以"哪一行在最上面"本来就是不定的。另外，
  推断解码的画面可能会整体偏左或偏右一点，因为行栅格是从信号里量出来的，而不是
  来自 VIS 头已知的时序。画面可读，但未必逐像素精确。
* **画质**：有 VIS 头时解码是精确的。推断解码在 PD、Martin、Robot 这几个系列上
  很接近，在 Scottie 系列上会差一些（它的同步脉冲最短）。

如果你已经知道是什么模式，**直接在 Mode 列表里选它**比让程序推断更好——那样用的
是精确时序，完全不涉及猜测。

**Save image...** 把结果存成 PNG 或 JPEG。

### 怎么看瀑布图

瀑布图横轴是频率、纵轴是时间（向下滚动），亮度代表信号强度——所以画面一行都
还没解出来的时候，你就能看出有没有信号进来。SSTV 的样子很好认：

| 看到的样子 | 说明 |
|---|---|
| 一条约占三分之一宽度的亮带，中间有**等间距的亮竖条梳齿** | 健康的 SSTV 信号。梳齿就是每行的同步脉冲，间距均匀说明能正常解码。 |
| 开头一小段很密集的花纹 | VIS 头——用来标明模式的那串音调。 |
| 一条始终不动的细亮线 | 是载波或啸叫，不是图像。 |
| 亮度铺满**整个宽度** | 音量太大，音频削波了，画面会撕裂。把音量调小。 |
| 一片没有结构的淡淡噪声 | 只有噪声。里面也许有信号，但强度不够。 |
| 亮带明显偏离 `sync` 刻度线 | 接收机频率偏了。解码会自动校正不大的偏移并报告校正量。 |

顶部刻度标出了四个关键频率——`sync` 1200 Hz、`black` 1500 Hz、`mid` 1900 Hz、
`white` 2300 Hz——所以频率偏了多少，直接看亮带相对这些刻度线偏在哪里就知道了。
**Frequency span** 用来缩放频率范围，**History** 选择显示多少秒，
**Suggested history for mode** 会按你预期收到的模式自动挑一个合适的长度。
把 **Show frequency scale** 取消勾选就只显示纯瀑布图。

瀑布图在录音时实时绘制；打开音频文件时也会一次性画出来，所以录完之后也能回看。

画面和瀑布图之间有一条**可以拖动的分隔条**，想让哪个大一点就拖它。窗口会按
**它所在的显示器**来定尺寸，不会跨到两块屏幕上；如果窗口高度不够放全部控件，
右侧控制栏会变成可滚动，而不是把下方的按钮挤没。

## 出问题时怎么办

| 现象 | 含义 |
|---|---|
| "No SSTV signal found"（没找到 SSTV 信号） | 音频里没有 VIS 头——可能是语音、噪声，或者这段录音不是从发送开始处截的。 |
| 画面撕裂或倾斜 | 收到的信号太弱，或者音频削波了。试试把播放音量调小。 |
| 形状对但颜色不对 | 通常是频率偏了；本程序会自动校正不大的偏移，并报告校正量。 |
| "Partly decoded ..."（只解出一部分） | 录音在发送结束前就断掉了。 |
| 设备列表是空的 | Windows 里没有本程序能看到的、已启用的音频设备。检查一下声音设置。 |
| 瀑布图上完全没有亮带 | 输入端口没有信号进来。检查电台音量、连线，以及是否选对了输入设备。 |

## 实现说明

* **无需安装步骤。** 程序依赖 NumPy 和 Pillow，它们已经放在同目录的
  `vendor/` 文件夹里，由 `sstv_bootstrap.py` 挂到模块搜索路径上。系统只需
  要有 Python 本身和它的标准库，以及 `tkinter`（python.org 的安装包自带）。
* **音频直接调用 Windows。** 播放和录音通过 `ctypes` 走 Win32 多媒体接口
  （winmm），所以没有 PortAudio、PyAudio 这类需要另行安装的依赖。WAV 文件的
  读写用的是标准库。
* **验证方式。** `run.bat --check` 会逐一编码并解码每一种模式，打印每次往返
  的峰值信噪比，并检查瀑布图。解码还另外验证了叠加噪声、衰减到满幅 8% 的
  弱信号，以及人为引入的频率偏移。

### 采样率

全部按 48 000 Hz 工作，这是 QSSTV 和 PySSTV 使用的采样率，也是声卡原生支持的
采样率。如果录音设备只支持 44 100 Hz，程序会自动重采样。

## 版本历史

`python sstv_app.py --version` 会直接从程序里打印这份记录。

### 1.1.0 — 2026-02-13

* **可以监听系统声音。** 接收机接在音箱上、或者信号在别的程序里播放（比如浏览器
  里的 WebSDR），现在不用任何连线就能解码。用的是 WASAPI 回环，所以不依赖大多数
  现代声卡驱动默认隐藏并禁用的"立体声混音"。
* **画面边收边画。** 不再等录完才开始解码：大约 1 秒后就开始逐行显示，画面自上而下
  填充。按停止也不再触发一次漫长的解码。
* **解码不再清空瀑布图。** 历史会保留，刚才在看的信号会留在屏幕上。
* **窗口按所在显示器定尺寸**，不再跨到两块屏幕上；窗口变矮时控制栏可滚动，底部
  的按钮仍然够得到。

### 1.0.0 — 2026-02-12

* 14 种主流 SSTV 模式的编码和解码。
* 单工操作：发送和接收是两个独立动作。
* 接收可来自麦克风或音频文件；发送可到扬声器或音频文件。
* 录音时实时显示瀑布图，带频率刻度和按模式适配的历史长度。
* 不需要指定模式，通过读取 VIS 头自动识别。

### 版本号

版本号只在一个地方定义——`sstv/version.py`——其他地方全部从它读取：窗口标题、
`--version`、自检、两份 README，以及打包文件夹的名字。所以不会出现"版本号改了一半"
的情况。

要升版本：

```
python tools\bump_version.py patch     # 1.1.0 -> 1.1.1   修 bug
python tools\bump_version.py minor     # 1.1.0 -> 1.2.0   加功能
python tools\bump_version.py major     # 1.1.0 -> 2.0.0   不兼容改动
python tools\bump_version.py 1.4.2     # 或者直接指定
```

它会更新版本号和发布日期（所有出现的地方），并打印出要粘到 `sstv/version.py` 里的
更新日志条目。另外 `python tools\bump_version.py --check` 会检查有没有哪个文件的
版本号或日期还停留在旧值。

## 文件结构

```
run.bat                 启动脚本
sstv_app.py             入口：窗口、--check、--encode、--decode
sstv_bootstrap.py       把 vendor/ 挂到模块搜索路径
sstv/
    modes.py            各模式的扫描方案：时序、音调、VIS 码
    encoder.py          图像 -> 音频
    decoder.py          音频 -> 图像
    dsp.py              调频调制、解调、滤波、频谱分析
    waterfall.py        瀑布图显示
    colorspace.py       RGB <-> YCrCb 色彩空间转换
    vis.py              从信号中读取模式标识（VIS 头）
    audio.py            WAV 文件、扬声器播放、麦克风采集
    wasapi.py           监听系统声音（WASAPI 回环）
    streaming.py        边收边解码，逐行显示画面
    version.py          版本号与更新历史
    gui.py              图形界面
tests/                  上面提到的各项验证脚本
```
